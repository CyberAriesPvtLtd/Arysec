Two days in a sandbox account finding the things that actually cause incidents: over-broad roles, a storage bucket someone opened for a demo, keys in a build log, and logging that was never switched on in the region where it mattered.

The Misconfiguration Is the Attack

Cloud incidents rarely start with a novel exploit. They start with an identity that can do more than anyone realised, a storage object made public for a quick demo, or an access key committed to a repository two years ago and never rotated. None of that is exotic, and all of it is findable before an attacker finds it.

The course runs in a sandbox account deliberately built with those problems in it. Delegates enumerate permissions the way an attacker would, follow a privilege escalation path, find exposed data, and then close each gap and verify the fix.

The second half is about knowing sooner. Logging that is actually enabled everywhere, alerts that fire on the handful of events that matter, and guardrails that stop the misconfiguration being created rather than reporting it a week later.

Content

Lab Modules

Identity and Privilege

Roles, policies and trust relationships. Enumerating effective permissions, finding escalation paths through pass-role and assume-role chains, and cutting privilege without breaking deployments.

Storage and Data Exposure

Buckets, blobs, snapshots and managed database endpoints. Finding what is reachable from the internet, what is reachable from any authenticated account, and what encryption actually protects.

Network Boundaries

Security groups, network security groups and firewall rules, private endpoints, egress control, and the management interfaces that quietly stay open to the world.

Secrets and Keys

Managed secret stores, workload identity instead of long-lived keys, rotation, and finding credentials already leaked into images, build logs and repositories.

Logging and Detection

Audit logs across every region and subscription, log integrity, retention that meets your obligations, and alerting on the small set of events that reliably precede an incident.

Guardrails and Drift

Preventive policy, infrastructure-as-code scanning in the pipeline, and detecting configuration drift when someone fixes production by hand at midnight.

How It Runs

From Scoping to Delivery

How a Cloud Security engagement runs, start to finish.

01

Platform Selection

One cloud per cohort. Multi-cloud teams run consecutive cohorts — a combined session covers three consoles badly rather than one well.

02

Sandbox Provisioning

We provision isolated accounts with the misconfigurations pre-planted, so nothing touches your production estate and everyone starts from the same state.

03

Two Lab Days

Day one attacks and fixes identity, storage and network. Day two builds the detection and guardrails that stop the same problems returning.

04

Baseline Handover

The hardening baseline, detection rules and policy examples are handed over as code, so they can go straight into your own repositories.

Benefits

What Changes Afterwards

Fewer Findings at the Next Review

Cloud configuration reviews repeat the same findings year after year in most organisations. Teams that have fixed them by hand once stop creating them.

Detection Where There Was None

A surprising number of organisations discover during this course that audit logging was never enabled in a region they have been using for two years.

Least Privilege That Ships

Privilege reduction usually stalls because nobody knows what will break. The enumeration method taught here makes the change measurable rather than a gamble.

Guardrails Instead of Nagging

Preventive policy in the pipeline removes a whole class of review comments and stops the argument being had again next quarter.
